# Lab snapshots

The course develops the `Calculator` example through manual COM, IDL, Automation, ATL, and
out-of-process hosting. Each lab names its starting code and prerequisites below.

**Stage 5 is self-contained:** its EXE server, DLL, client, and proxy/stub build together.
It uses dedicated identifiers and does not need earlier lab binaries or registrations.
The progression below describes concepts, not a Stage 5 build dependency chain.

```
   Stage 1 ──► Stage 2 ──► Stage 3 ──► Stage 4 ──► Stage 5
   manual      in-proc      IDL +       ATL          EXE + DLL
   IUnknown    DLL server   proxy/stub  rewrite      hosting
```

## The five stages

| Stage | Folder | What you get | Labs that start here |
|---|---|---|---|
| 1 | [`stage-1-manual-iunknown/`](stage-1-manual-iunknown/) | `Calculator` with hand-written `IUnknown`, no COM runtime involved | 1.1, 1.2 |
| 2 | [`stage-2-inproc-server/`](stage-2-inproc-server/) | The same object as a registered in-proc DLL server, plus a client | 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 6.1 |
| 3 | [`stage-3-idl-marshaling/`](stage-3-idl-marshaling/) | `ICalculator` in IDL, MIDL output, and a proxy/stub DLL | 4.1, 4.2, 4.3 |
| 4 | [`stage-4-atl-server/`](stage-4-atl-server/) | The dual-interface ATL rewrite with a type library and events | 5.1, 5.2, 6.2, 6.3 |
| 5 | [`stage-5-exe-server/`](stage-5-exe-server/) | EXE server, surrogate-capable DLL, client, and matching proxy/stub | 7.1, 7.2, 7.3 |

Labs 1.3, 8.1 and 8.2 need no starting code at all.

## How to use a stage

Each stage folder has its own `README.md` with exact steps, but the shape is always the same:

1. Open the stage's **`.sln`** (Stage 3 has a `.vcxproj`; Stage 4 is wizard-generated).
2. Choose **Debug | x64** — or **x86** where a lab asks for it.
3. **Build → Build Solution**, or press **F5** to build and debug.
4. Follow the stage README's registration and verification steps before starting the lab.

Everything builds into `x64\` or `x86\` inside the stage folder, so the paths in each README apply
regardless of Debug or Release.

| Stage | Open this | Notes |
|---|---|---|
| 1 | `Lab01.sln` | Console app |
| 2 | `Stage2.sln` | The DLL and its client. `Calc.def` is pre-wired into the linker |
| 3 | `CalcPS.vcxproj` | An NMake project — MIDL generates its own sources, which a normal C++ project cannot express cleanly. The commands are written out in the file |
| 4 | *(none)* | ATL is generated by the VS wizard; the README is the recipe |
| 5 | `Stage5.sln` | Four projects; native MIDL build support. Run `Setup.ps1` once, then choose EXE, surrogate, or in-process hosting with client options |

> Registration always needs an **elevated** prompt, because `regsvr32` and `-RegServer` write to
> `HKLM`. Visual Studio does not need to be elevated — only the registration step does.

## Working copies

Build output and any edits you make are ignored by git (see [`.gitignore`](.gitignore)), so you can
break a stage freely. To get back to a clean copy:

```powershell
git checkout -- labs/stage-2-inproc-server
git clean -fd labs/stage-2-inproc-server
```

Several labs ask you to **deliberately break** the code. Do that in a copy if you want to keep the
original around:

```powershell
Copy-Item labs\stage-2-inproc-server work\lab-2-4 -Recurse
```

## A note on GUIDs

Earlier snapshots use the placeholder GUIDs below. **Stage 5 has its own IID, CLSIDs, and AppIDs**,
listed in its [registration reference](stage-5-exe-server/README.md#registration-reference), so its
two-method interface and hosting registrations do not replace earlier components.

| Name | GUID |
|---|---|
| `IID_ICalculator` | `{A1B2C3D4-0001-4000-9000-000000000001}` |
| `IID_IAdvancedCalculator` | `{A1B2C3D4-0002-4000-9000-000000000002}` |
| `CLSID_Calculator` | `{A1B2C3D4-1111-4000-9000-000000000001}` |
| `LIBID_TrainingCalcLib` | `{A1B2C3D4-9999-4000-9000-000000000099}` |

**These are for learning only.** Generate your own with `New-Guid` for anything you ship — Module 4
explains why reusing an IID for a changed interface is one of the worst bugs in COM.
